# **AI 实地叙事导览 Agent MVP 项目方案**

---

## 一、项目名称

# **会走路的村庄**

### 副标题

**基于游客画像、真实点位与在地故事的 AI 乡村漫游 Agent**

---

## 二、项目一句话介绍

**《会走路的村庄》是一个面向乡村文旅场景的 AI 实地叙事导览 Agent。系统根据游客身份、兴趣、时间等信息，自动生成一条个性化村庄漫游路线，并在每个点位生成专属故事、观察任务、拍照提示和互动问题。体验结束后，AI 会生成一份属于游客自己的村庄观察报告或古村故事卡片。**

---

## 三、项目背景

当前乡村文旅项目中，很多村庄已经拥有丰富的自然景观、历史建筑、民宿空间、农产品、乡建故事和新村民实践，但这些内容往往存在几个问题：

第一，村庄内容分散。老屋、农园、民宿、公共空间、村民故事等资源各自存在，缺少一条能够被游客理解和体验的叙事线。

第二，传统导览方式单一。大多数导览系统只是固定讲解，所有游客看到的是同一套内容，缺少个性化、互动性和参与感。

第三，游客停留浅。游客往往只是拍照、打卡、离开，很难真正理解村庄背后的生活、人物、历史和乡建价值。

第四，在地故事难以转化为体验产品。村庄有故事、有空间、有产业，但缺少一个轻量化工具，把这些内容转化为可体验、可传播、可复用的文旅产品。

因此，我们希望用 AI 重新组织村庄内容，让村庄从一个“被观看的空间”，变成一个“会回应游客、会生成故事、会引导行动”的互动场景。

---

## 四、项目定位

《会走路的村庄》不是普通的 AI 导览系统，而是一个将真实村庄空间、在地故事和游客行动连接起来的 **AI 田野叙事 Agent**。

它的核心不是“讲解一个景点”，而是让游客以不同身份进入村庄，完成一次带有角色感、任务感和生成感的乡村漫游。

传统导览是：

> 所有人听同一个故事。

我们的系统是：

> 每个人走出自己的村庄剧本。

## 五、项目目标

### 1. 黑客松 MVP 目标

在 2 天内完成一个可以室内路演展示的 H5 Demo，跑通完整体验闭环：

> 用户选择身份与兴趣  
> AI 生成个性化路线  
> 用户进入点位体验  
> AI 生成点位故事与任务  
> 用户输入个人感受  
> AI 生成最终观察报告 / 故事卡片

### 2. 路演展示目标

由于路演在室内进行，本项目 MVP 不依赖真实户外行走，而采用：

> **室内模拟漫游 + 点位二维码辅助验证 + 屏幕完整演示体验闭环**

评委可以在室内通过网页模拟一次村庄漫游，看到系统如何根据不同用户生成不同路线、不同故事和不同任务。

### 3. 长期目标

未来将该系统扩展为乡村文旅 AI 导览工具，可复制到不同村庄，形成：

- 乡村 AI 漫游小程序
    
- 古村导览 SaaS 模板
    
- 研学路线生成工具
    
- 民宿 / 营地增值体验产品
    
- 在地故事共创平台

## 七、核心痛点

### 痛点一：游客看得见村庄，但看不懂村庄

很多游客进入村庄后，只能看到建筑、街巷、自然景观，却不了解背后的村民生活、历史记忆、乡建实践和产业变化。

### 痛点二：传统导览缺少个性化

同一个点位，对亲子家庭、摄影爱好者、乡建研究者和城市白领来说，关注点完全不同。但传统导览通常只提供一套固定讲解。

### 痛点三：村庄内容难以被有效组织

村庄里的老屋、植物、农园、民宿、餐厅、村民故事、新村民创业等内容很丰富，但缺少一个系统将其串联成可体验的路线。

### 痛点四：游客缺少参与感和记忆沉淀

很多游客只是拍照打卡，没有被引导去观察、提问、记录和表达。游览结束后，也没有形成属于自己的内容成果。

---

## 八、解决方案

《会走路的村庄》通过 AI Agent 将村庄内容转化为个性化漫游体验。

系统基于三类信息进行生成：

1. **游客信息**  
    包括身份、兴趣、时间、偏好等。
    
2. **村庄信息**  
    包括点位资料、真实故事、照片、标签、可观察细节、任务模板等。
    
3. **现场体验信息**  
    包括用户在每个点位的输入、感受、回答和记录。
    

最终实现：

> 从“固定导览”到“个性化路线”；  
> 从“景点介绍”到“故事任务”；  
> 从“被动参观”到“主动观察”；  
> 从“一次游览”到“一份个人记忆”。

## 九、MVP 核心功能

### 功能一：游客身份测试

用户进入页面后，回答 3 个问题：

1. 你是谁？
    
    - 亲子家庭
        
    - 摄影爱好者
        
    - 乡建研究者
        
    - 数字游民
        
    - 城市白领
        
    - 学生
        
2. 你今天更想体验什么？
    
    - 老屋与乡愁
        
    - 自然植物
        
    - 新村民生活
        
    - 乡村创业
        
    - 夜晚与星空
        
    - 亲子探索
        
3. 你有多少时间？
    
    - 30 分钟
        
    - 45 分钟
        
    - 60 分钟
        

系统根据选择生成一个游客身份标签，例如：

- 亲子自然探索家
    
- 乡野摄影猎人
    
- 老屋记忆采集员
    
- 新村民创业观察员
    
- 慢生活疗愈者
    
- 村庄声音收集员
    

---

### 功能二：AI 生成个性化路线

系统根据用户身份、兴趣和时间，生成一条村庄路线。

MVP 阶段预设 3 条主要路线：

## 1. 老屋认租线

适合人群：乡建研究者、城市白领、建筑兴趣者  
体验重点：老屋、空间更新、村庄记忆、未来共创  
点位示例：村口 → 老屋 → 公共空间 → 新村民空间 → 民宿

## 2. 柿子与乡愁线

适合人群：亲子家庭、摄影爱好者、慢生活游客  
体验重点：植物、季节、乡愁、自然观察  
点位示例：村口 → 柿子树 / 农园 → 老屋 → 公共空间 → 咖啡屋

## 3. 新村民创业线

适合人群：数字游民、青年创业者、乡建观察者  
体验重点：民宿、咖啡、餐厅、农场、青年实践  
点位示例：民宿 → 咖啡屋 → 餐厅 → 农场 → 公共空间

MVP 中路线生成采用：

> **规则匹配点位 + AI 生成路线叙事文案**

这样既保证系统稳定，又能体现 AI 生成能力。

---

### 功能三：点位故事生成

用户进入某个点位后，系统根据用户身份和点位资料，生成个性化点位内容。

每个点位页面包含：

- 点位名称
    
- 点位照片
    
- 真实点位介绍
    
- AI 生成故事
    
- 观察任务
    
- 拍照提示
    
- 采访问题
    
- 用户输入框
    

例如，同样是“老屋”点位：

对摄影爱好者，系统强调光影、材质和时间痕迹。

对乡建研究者，系统强调空间更新、老屋再利用和乡建价值。

对亲子家庭，系统强调材料观察、生活想象和儿童任务。

---

### 功能四：游客互动记录

用户在每个点位可以输入一句话，例如：

- 我在这里看到了什么？
    
- 我想到了什么？
    
- 我想问村庄一个什么问题？
    
- 我想给这个地方留下一句话。
    

这些输入会被系统保存，并用于最终报告生成。

MVP 阶段不做复杂图片上传，优先完成文字输入闭环。

---

### 功能五：最终报告 / 故事卡生成

用户体验完 3～5 个点位后，AI 生成一份专属内容。

可生成两种形式：

## 1. 深度版

# **《我的龙潭 / 四坪村田野观察报告》**

内容包括：

- 我的身份
    
- 我的路线
    
- 我走过的点位
    
- 我的观察瞬间
    
- 我的输入内容
    
- AI 总结
    
- 下次推荐路线
    

## 2. 传播版

# **《我的古村故事卡片》**

适合用于朋友圈、小红书、社群传播。

示例文案：

> 今天，我以“乡野摄影猎人”的身份打开了四坪村。  
> 我在老屋前寻找时间的纹理，在柿子树下记录季节的颜色，也在咖啡屋旁看见新村民的生活方式。  
> 这不是一次普通的游览，而是一次我和村庄共同生成的故事。

## 十、MVP 点位设计

MVP 阶段只做 5 个点位，保证内容完整、体验清晰、开发可控。

### 点位一：村口

功能：村庄入口与身份确认  
体验重点：进入村庄、选择观看方式  
任务示例：给今天的自己选择一个村庄身份  
标签：入口、初见、路线开始、村庄印象

### 点位二：老屋

功能：乡愁、建筑、空间更新  
体验重点：旧生活痕迹、老屋再利用  
任务示例：拍下一处你认为最有时间感的细节  
标签：老屋、乡愁、建筑、记忆、乡建

### 点位三：柿子树 / 农园

功能：自然、季节、亲子、摄影  
体验重点：植物观察、食物记忆、乡村季节感  
任务示例：寻找三种颜色或三种自然细节  
标签：植物、自然、季节、农园、亲子

### 点位四：咖啡屋 / 民宿 / 餐厅

功能：新村民生活、乡村创业、消费转化  
体验重点：乡村新业态、青年返乡、生活方式  
任务示例：观察一种新的乡村生活方式  
标签：新村民、创业、民宿、咖啡、生活方式

### 点位五：公共空间 / 山路 / 星空点

功能：停留、总结、慢生活  
体验重点：村庄公共生活、夜晚、山野感受  
任务示例：写下一句想留给这个村庄的话  
标签：公共空间、慢生活、山路、星空、停留

## 十一、室内路演展示方案

由于路演在室内进行，MVP 演示采用“模拟实地漫游”方式。

### 演示逻辑

1. 主讲人设定一个游客场景  
    例如：一位摄影爱好者来到四坪村，只有 45 分钟，想寻找老屋、植物和乡愁感。
    
2. 在首页完成身份选择  
    选择：摄影爱好者、老屋与乡愁、45 分钟。
    
3. 系统生成身份和路线  
    例如：  
    身份：乡野摄影猎人  
    路线：柿子与乡愁线  
    点位：村口 → 柿子树 → 老屋 → 农园 → 咖啡屋
    
4. 点击进入点位  
    模拟游客到达“柿子树”或“老屋”。
    
5. 系统生成点位内容  
    包括故事、任务、拍照提示和采访问题。
    
6. 用户输入一句感受  
    例如：这棵树让我想到小时候外婆家的院子。
    
7. 继续体验 2～3 个点位  
    展示系统如何生成不同点位内容。
    
8. 生成最终故事卡  
    展示《我的古村故事卡片》或《我的田野观察报告》。

## 十二、二维码设计策略

扫码功能保留，但不作为室内路演的主流程。

MVP 中可以为每个点位生成一个二维码，制作成“点位卡”。

每张点位卡包括：

- 点位名称
    
- 点位照片
    
- 一句话介绍
    
- 二维码
    

路演时说明：

> 由于今天是室内演示，我们用屏幕点击模拟游客到达点位。但系统已经支持点位二维码。未来只需要将二维码贴到村庄真实点位，游客就可以在现场扫码触发对应故事和任务。

这样既适应室内路演环境，又保留真实落地逻辑。

## 十四、技术实现方案

### 1. 前端

建议使用 H5 网页，适配电脑投屏和手机访问。

可选技术：

- Vue / React / Next.js
    
- Vite 快速搭建
    
- Tailwind CSS / Ant Design Mobile / shadcn UI
    
- 简单动画增强体验
    

前端负责：

- 页面展示
    
- 用户选择
    
- 路线展示
    
- 点位切换
    
- 用户输入
    
- 报告展示
    
- 二维码跳转页面
    

---

### 2. 后端

可选技术：

- Python FastAPI
    
- Node.js Express / NestJS
    
- Java Spring Boot
    
- Flask
    

后端负责：

- 点位数据读取
    
- 用户画像生成
    
- 路线匹配
    
- 大模型调用
    
- 点位故事生成
    
- 用户输入保存
    
- 最终报告生成
    

---

### 3. 数据库

MVP 阶段建议轻量实现。

可选方式：

- JSON 文件
    
- MySQL
    

最推荐 MVP 方式：

> 点位数据用 JSON 文件维护，用户输入可存在 SQLite 或内存 Session 中。

这样开发最快、风险最低。

---

### 4. AI 生成策略

MVP 不建议完全依赖 AI 自主规划，容易不稳定。

采用：

> **规则匹配 + AI 文案生成**

具体方式：

1. 后端根据用户身份、兴趣和时间，用规则选出路线。
    
2. 根据点位资料和用户身份，调用大模型生成点位故事、任务和问题。
    
3. 根据用户输入和走过点位，调用大模型生成最终报告。

## 十五、核心接口设计

### 1. 提交用户选择接口

```http
POST /api/profile
```

请求示例：

```json
{
  "role": "摄影爱好者",
  "interest": "老屋与乡愁",
  "duration": "45分钟"
}
```

返回示例：

```json
{
  "session_id": "abc123",
  "generated_identity": "乡野摄影猎人",
  "route_name": "柿子与乡愁线",
  "route_intro": "这条路线将带你从村口进入村庄的季节与时间感，在柿子树下观察自然，在老屋前寻找生活痕迹，最后抵达咖啡屋，看见乡村新的生活方式。",
  "spots": ["village_gate", "persimmon_tree", "old_house", "farm", "cafe"]
}
```

---

### 2. 获取点位内容接口

```http
GET /api/spot/{spot_id}?session_id=abc123
```

返回示例：

```json
{
  "spot_id": "old_house",
  "spot_name": "老屋",
  "image": "/images/old_house.jpg",
  "intro": "这是一栋保留较完整的传统老屋，见证了村庄生活方式的变迁。",
  "ai_story": "你现在站在一栋老屋前。请不要急着拍全景，先靠近它的门、窗和墙面。这里最动人的不是建筑本身，而是时间留下的纹理。",
  "task": "拍下一处你认为最有时间感的细节。",
  "photo_tip": "尝试从门框、瓦片或墙面裂纹中寻找时间的痕迹。",
  "interview_question": "如果遇到村民，可以问一句：这栋屋子以前住着什么样的人？"
}
```

---

### 3. 提交用户点位输入接口

```http
POST /api/note
```

请求示例：

```json
{
  "session_id": "abc123",
  "spot_id": "old_house",
  "note": "这栋老屋让我想到小时候外婆家的院子。"

```

```json

```

---

### 4. 生成报告接口

```http
POST /api/report
```

请求示例：

```json
{
  "session_id": "abc123"
```

- 采用结构化 Prompt

## 二十五、路演核心表达

### 开场表达

很多乡村并不缺风景，也不缺故事，缺的是一种让游客真正走进去、看懂它、记住它的方式。

我们做的《会走路的村庄》，就是希望用 AI 把村庄里的老屋、植物、民宿、村民故事和游客行动连接起来。

### 核心金句

> 我们不是做一个 AI 导览系统，而是让村庄拥有一种新的叙事能力。

> 传统导览是所有人听同一个故事，而我们希望每个人走出自己的村庄剧本。

> AI 不只是在屏幕里生成文字，它可以被放进老屋、树下、山路和村民故事之中。

> 游客不是来打卡一个村庄，而是和这个村庄共同生成一段记忆。

> 《会走路的村庄》让乡村从一个被观看的空间，变成一个会回应人的故事系统。

## 二十六、项目最终总结

**《会走路的村庄》是一个将 AI 生成能力嵌入真实乡村空间的实地叙事导览 Agent。**

它通过游客画像、点位资料库和大模型生成能力，为不同游客生成不同路线、故事、任务和报告。

在黑客松 MVP 阶段，我们将完成一个可室内演示的 H5 Demo，让评委在屏幕上体验一次完整的 AI 村庄漫游。

未来，该项目可以进一步落地到真实村庄，通过二维码、地图、声音、留言墙和内容共创机制，成为乡村文旅、研学、民宿和乡建传播的新型基础设施。
